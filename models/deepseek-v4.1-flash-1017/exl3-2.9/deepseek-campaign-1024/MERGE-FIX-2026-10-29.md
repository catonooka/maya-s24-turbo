# Upstream merge crash — root cause & fix (2026-10-29)

Engine `~/maya-ds4-main` branch `mixed-lane`. Merge of 100 upstream commits (`cead29b8`,
fixups `e90e408d`) crashed with CUDA illegal access at first inference. Fixed in
`a7b02ed0` + `f50ddac2`. This file is the full record.

## Root causes (2 bugs, both in the seam between upstream's refactor and our S1 mixed-K pack)

1. **CPU-lane answer protocol delivers NaN.** Upstream's lane worker answers the very
   first window (resp: `cpu0=1 seq=1 sq=1 part=-nan -nan -nan`); parent's lane never
   answers window 1 (`cpu0=0`). The NaN poisons layer-0's `moe_out` → NaN cascade →
   first illegal access surfaces ~layer 2 in `exl3 win_experts`. The exact defect inside
   the lane loop was never pinned (x input, weights, quant calls and `cpu_experts_iq`
   all verified identical) — the answer path itself is what differs.
2. **Device-side `wait_seq` spin hangs once the lane is off.** `layer()` launches a
   spin kernel "until `resps[slot].seq == sq`"; with the lane never acking it spins
   forever → main thread stuck in `cuStreamSynchronize` mid-generation (verified by
   thread-1 gdb backtrace; all 16 lane workers idle on their queue = harmless).

## Fixes (both env-gated, default = lane answering OFF)

- `g_no_lane` (file scope): `DS4_CPU_LANE=1` re-enables the upstream lane protocol.
- Gated sites in `ds4_model.cu`: `route_publish(... reqs+slot ...)` → nullptr;
  `ma.cpu_part`/`ma.cpu_flag`; `wa.cpu_part`/`wa.cpu_flag`/`wa.wait_ptr`; `wait_seq(...)`.
- Kept parent's `src/prefill/`, `src/ds4/ds4_iq.cu`/`.cuh`, `src/ds4/ds4_iq_cpu.cpp`
  (with upstream's `dense_requant` grafted in — merged `mat_bf16` needs it).
  `ds4_gguf.cu` = parent + merge shim; `ds4_kernels.cu` = parent + compat shim.

## Proof trail (twin-run method: identical print in both trees, first divergent value)

All of these were **bit-identical** between merged-crashing and good binaries, i.e.
exonerated as crash causes: gate logits `glog` il=0, gate biases, routing weights `rw`,
plan ring entries (structure AND order), expert blob bytes at plan pointers
(`c4 ad 0e 35 ...` identical), mix tables (per-class lo/hi spans, suh/svh, k2), expert
grouping (`gs/ge/ng`), shared-expert output `shout`, attention input x, `cpu_experts_iq`
source text, `mx_part_ptr`/`mx_mat`/RAM staging code, expert-layout tables.
NaN appeared strictly between clean `shout` and `moe_out` at layer 0, and the resp slot
dump (`cpu0/seq/part`) was the discriminator that caught the lane.

Also useful: `compute-sanitizer --tool memcheck` on the one-shot raw harness is bounded
(~8 min: load phase is CPU-bound, inference is seconds under sanitizer) and named the
first faulting kernel (`route_publish_kernel` shared read at 0xfffffffc — turned out to
be a benign-ish OOB in the topk path, present in parent too; NOT the crash cause).

## Prefill push (2026-10-29, later) — 497 → 598/738 t/s

**single-GPU by design** — the S3 layer-major run executes every trunk layer on GPU0
(GPU1 spin-waits at 141 W / 100% util / 0% mem; only prompt-skip crumbs, 320k vs 12.9M

## Lane fix + speed reality (Oct 29 evening)
- ROOT CAUSE of babble: merged part() read mixed experts via the uniform hl layout (never built for
  arena layers -> zero offsets, k=n=0). The fork's own part() (pre-merge) had the esrc+clay branch;
  the merge conflict took upstream's side. Fix = re-adopt: commit 167a620b.
- Verified: 40-seed one-shot clean (0 NaN/illegal), quality gate 7/7 (needle30k PASSES now),
  hello/17x19/chain-math correct, server live.
- Decode with lane ON: 12-15 t/s (chat 12-14, @800 prose 15.1-15.4 engine-line) vs 62.7 lane-off.
  Cause: 67.6% of routed picks on the CPU lane (only 3229/15744 experts fit VRAM), ~36ms CPU/token.
  Parent-era parity: same 16-thread lane, same placement (3207 vs 3229 experts in VRAM).
- Tested, no material change: dspark off (12.4 vs 14.3), STRATA_DS4_CPU_LANE=smt (12.3),
  MAYA_DS4_STREAM=1 (no-op: lane_layer_ok is kFmtMXFP4-only - decode streaming is GGUF-only),
  warm 647-tok prompt (7.8 - generation experts drift). Box = 3955WX 16c/32t; lane uses all 16 cores.
- NEXT (the real fix): extend decode PCIe streaming to EXL3 mixed (prefill already streams EXL3
  chunks at 1222 t/s @100k; lane_layer_ok + decode plan2 machinery). Multi-hour, checkpointed.
